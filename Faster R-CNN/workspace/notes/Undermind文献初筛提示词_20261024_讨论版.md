# Undermind文献初筛提示词 第一版 讨论版

此版用于方法与代码初筛；公开数据扩充完成后，再更新任务条件和候选排序。本文只准备提示词，没有启动调研或选定基线。

## 使用顺序（2026-10-24分步修订）

先 **Deep search检索**，完成后再 **Write report分析并写报告**。两步在同一工作区、优先同一聊天中衔接；分别复制对应代码块里的文字，不要把整份文件一次发过去。Organize papers用于整理已有论文，是可选操作，不是写报告前的必要步骤。

|步骤|点击入口|复制内容|预期结果|
|---|---|---|---|
|1 现在做|Deep search|下方“检索提示词”代码块|相关论文、可获取的代码线索及简短初筛记录|
|2 检索完成后做|Write report|下方“报告提示词”代码块|基于本轮检索结果的中文分析报告、分表和暂定优先级|
|3 可选，当前不必做|Organize papers|文末“整理短指令”代码块|把已有论文归入文件夹，便于后续阅读|

**发送检索提示词后，还要留意是否需要启动：**若回复末尾出现Search proposal卡片及Launch / Edit，并明确写“草案尚未运行”，则当前只是预检索或搜索方案，正式Deep search尚未开始。核对卡片范围符合本提示词后，点击 **Launch**；只有范围有误才用Edit修改。不必重发第一段，也不要此时直接转Write report。等待实际深搜完成，再依据其结果进行第2步。2026-10-24用户回传的草案为“Conductor Defect Detection with Limited Labels”，范围基本符合，当前下一操作是Launch；助手未代为启动。

若第1步已同时生成符合第2步全部要求的报告，就不必重复生成。若换了聊天，先确认本轮检索结果已纳入聊天上下文；不要让报告从空白资料开始。完成后带回报告及论文、代码链接清单；有澄清问题或代码访问限制也一并说明。最终代码可用性仍需后续实际核对。

依据：用户提供的当前网页截图，以及[Undermind官方工作区介绍](https://app.undermind.ai/)和[官方检索到报告的流程说明](https://www.undermind.ai/)。以上是本项目的操作建议，未替用户点击或启动任务。

## 第1步：Deep search — 检索提示词

只复制下面这个代码块。若出现范围澄清，沿用其中的三类方向与代码要求回答；不确定的问题可以带回讨论。

```text
请为我的目标检测研究进行文献检索和初步筛选。本轮先找到论文和可追溯的实现线索，返回候选清单与简短检索总结；完整比较报告随后再基于本轮结果撰写。

应用背景：输电导线断股、松股两类缺陷的矩形框检测。现有153张人工标注图片，正在扩充公开数据，最终数量、类别分布与缺陷尺度尚未确定。关注大图中的局部细小、细长、纹理变化不明显的缺陷及标注有限的问题。不要据此直接断言全部目标符合某个固定小目标定义。

同时检索导线/工业缺陷应用论文及可迁移的通用目标检测方法，不能只搜带“导线”关键词的论文。主要围绕：
1. 小目标检测：细节保留、特征表达、多尺度处理、监督与定位等。
2. 少数据/少样本检测：标注有限时的学习、迁移或适配；区分少量图片的常规两类检测与依赖基础类别和新类别K-shot适配的方法，注明额外数据需求。
3. 小目标与少样本结合：优先寻找实际同时验证两种困难的研究；直接相关工作不足时如实说明。
补充关注分类分数与定位质量的协调、候选排序、任务对齐等机制。

以近年研究为重点，保留必要的早期代表工作，检索截至实际执行日期，不机械限于2022—2025年。不要把简单切块预设为核心创新；普通导线分割、整图分类、无监督异常检测若仅提供间接启发，单独标明。

优先寻找有实际公开代码的工作，因为后续基线必须具备代码。无代码但思路有价值的论文可以保留作参考。核实论文、作者项目页和可访问的仓库线索，区分官方、第三方、尚未发布、未找到及无法核实。不要把“将开源”、空仓库或只有推理演示当作完整复现代码；也不要因摘要里没有代码链接就直接断定无代码。

请返回去重候选清单：英文标题、作者、年份、发表渠道或预印本状态、论文链接、所属方向、简短相关性理由、代码链接及当前可核实状态、明显的额外数据或任务设定要求。优先使用原论文和作者来源，关键判断保留链接；无法核实就明确写未知。

本轮候选数量由相关性决定，不用只为凑数纳入无关论文，也不必把检索范围提前压缩到最终报告的8—12篇。最后简短说明检索日期、关键词组合、各方向覆盖情况和主要缺口。暂不选定最终基线，不写完整长报告，不要求我重查旧153张图片，不安装软件或运行模型。
```

## 第2步：Write report — 报告提示词

等第1步检索完成后再发送下面这个代码块。报告使用已有检索结果；阅读候选全文、核实代码证据属于这一步的分析工作。

```text
请基于本工作区刚完成的文献检索结果，用中文撰写目标检测研究的文献初筛报告，供后续讨论和选择复现对象。先确认你能访问本轮检索结果；若没有这些资料，请指出缺少什么，不要凭记忆另造一份清单。保留论文英文标题、方法名称和原始链接。

不从头重复整轮宽泛检索。请在已有候选上深入阅读和核查论文、补充材料、作者项目及代码；若发现影响结论的关键文献缺口，先在报告中注明建议补检索的方向。不要把报告写作当成已经完成代码复现或模型选型。

### 研究背景和当前目标

我的最终应用是输电导线的断股、松股两类缺陷检测，输出缺陷区域的矩形框及类别。现有153张人工标注图片，正在寻找公开缺陷数据扩充，最终图像数量、两类数量、缺陷尺度分布和来源组成尚未确定。主要关注大图中局部细小、细长、纹理变化不明显的缺陷，以及标注数据有限时的学习效果；不要把“图片大”直接等同于所有目标都符合某个固定小目标定义。

当前是文献和代码初筛阶段：先了解有哪些相关方法、方法依赖什么条件、哪些具备实际复现入口。不要现在替我锁定最终模型、冻结训练参数或设计整套实验；这些会在数据扩充后再确定。无需等待我提供最终数据规模才开始调研，也不要要求我先重新检查全部旧图片或运行模型诊断。

请同时覆盖导线/工业缺陷应用论文和可迁移的通用目标检测方法。论文不必含“导线”关键词；通用方法只要针对下面的问题，并能说明与本任务的联系，就可以纳入。

### 三类主要方向和一个补充机制

1. **小目标检测**：关注局部细小目标的特征保留、特征表达、多尺度处理、监督或定位等方法。说明作者如何定义和评估小目标、采用何种图像尺度，以及是否必须依赖切块。切块可以作为方法背景或比较手段，但不要把简单切块本身预设为论文核心创新。
2. **少数据/少样本目标检测**：寻找标注有限时仍值得复现的学习、迁移或适配方法。必须区分少量标注图片的常规两类检测，与需要大量基础类别数据、随后在新类别进行K-shot适配的设定；还要明确K-shot按图片、实例还是类别计数。不要直接把“153张图”换算成某个K-shot设置。
3. **小目标与少样本结合**：寻找同时针对目标小和标注少的工作。区分论文真正验证了二者结合，与仅在题目或动机中提到两者；如果直接符合且有代码的工作不足，请如实说明，不强行凑数。
4. **补充机制：分类与定位质量协调**。关注分类分数、定位质量、候选排序或任务对齐之间的关系。说明它是可直接比较的完整方法，还是适合以后参考的组件；不要把分类分数直接当作定位准确率，也不要预设这些机制一定能解决我的数据问题。

从检索结果中以近年研究为重点，保留理解主线或构建可靠基线所需的早期代表工作。记录本轮检索的实际日期，不机械限于2022—2025年。三类方向不需要相同篇数，同一论文涉及多个方向时只列一条并交叉标记。

### 基线候选的代码要求

这是硬性筛选条件：**只有已能获取实际实现代码的论文，才可能进入我的基线复现候选；无代码论文仅供研究思路参考。**不要建议我从零按论文重写算法来充当基线。

对每篇核心论文明确填写代码状态和证据：

- 有官方代码：给出作者关联的仓库/项目链接，核查实际文件是否包含与论文方法对应的模型实现、训练入口或接入方式、配置和评价流程；记录依赖框架、所需预训练权重及说明是否齐备。
- 有第三方实现：单独标明非官方、实现者、对应论文与差异是否已核实。可以列作备选，但优先级不能自动等同于完整官方实现。
- 未发现代码、尚未发布、空仓库、只有推理演示或链接失效：明确具体情况，归入思路参考或待核实，不计入可复现基线名额。
- 无法访问仓库时写“代码状态未核实”，不要写成“无代码”，也不要凭论文的“将开源”承诺写成“已有代码”。

有代码仅是必要条件。请继续核对额外标注/基础类别数据、预训练、支持集构造、训练和评估设定等要求，指出哪些条件目前未知。不要把已找到代码写成已成功复现；本轮不安装软件或运行训练。对于显存、运行时间等，区分论文报告值、仓库说明和你自己的估计；没有依据时标为未知，不编造设备要求或假定我有大型计算集群。

### 证据和取舍要求

以原论文、补充材料、作者项目和代码仓库为主要依据；聚合页只作检索线索。重点候选应尽量查全文中的方法、数据与实验设置。无法读到全文时注明仅核查了摘要或可访问内容，不凭摘要补造实现细节。

保留论文标题、作者、年份、发表渠道或预印本状态、DOI/论文链接以及代码链接，并为关键判断提供可追溯依据。区分“论文证据支持”“对本任务的迁移推测”和“还需验证”。不同数据集、数据量、预训练和指标下的成绩不能直接排序成谁最适合我。

普通导线分割、整图缺陷分类及无监督异常检测若只有间接启发，可单独备注；不要冒充两类矩形框检测的直接基线。不要因当前153张而拒绝所有需要较多数据的方法，但必须明确它们依赖的条件，留待扩充后复核。

### 报告形式

1. 用简短文字回答：三类主要方向中哪些值得优先关注，有哪些设定不匹配或证据缺口？列出检索日期与主要关键词组合。
2. 总计约8—12篇去重核心论文，分成两张表：**有代码的基线候选**和**无代码/代码不可用或未核实的思路参考**。每条包含方向、论文信息与链接、核心机制、代码状态与仓库链接、数据/预训练要求、与本任务的联系、复现难点。相关性比数量重要；不要只为达到数量纳入不相关论文。
3. 从已核实有代码的条目中，暂列2—3个优先进一步核查的对象，逐项说明理由、必要条件和可能不适用之处。达标项不足就明确不足，不用无代码项补齐。此处是条件性的初筛顺序，不是最终选模结论。
4. 另列少量值得参考的研究思路及其证据来源，不把没有代码的灵感写成已准备复现的baseline，不预设拼接模块就是创新。
5. 最后列出数据扩充完成后需要补充的信息，以及这些信息可能怎样改变方法排序，例如两类样本/实例数量、缺陷尺度、图像来源差异和可用算力。不要要求为此另开旧153张全量诊断。

请把注意力放在“哪些方法有依据、代码到底是否可用、为什么值得考虑以及还缺什么条件”，避免用大量论文名称或未经核实的精度数字代替判断。返回可追溯引用的报告和论文清单即可，本轮不开展模型实验。
```
