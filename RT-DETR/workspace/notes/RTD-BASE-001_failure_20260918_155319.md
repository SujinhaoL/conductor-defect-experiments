## Failure reason

Ultralytics 8.4.152 created `labels/train.cache` and `labels/val.cache` inside the central dataset even though the requested training argument was `cache=False`. These are framework label-index caches rather than changes to image or label contents, but their creation violates the explicit requirement that all new RT-DETR files remain under the RT-DETR project and that the central dataset remain unchanged. The run was therefore stopped during training and was not resumed.

The two generated cache files were moved into the RT-DETR analysis directory for audit. The AMP self-check also downloaded `yolo26n.pt` into the locked Ultralytics source tree; that newly generated file was moved into the RT-DETR weights directory. No historical YOLO11 file was modified, deleted, moved, or overwritten.

After cleanup, the central dataset exactly matches the pre-training manifest: 309 files, zero differences, manifest SHA256 `4f08a1404fceb6f3eb163d34f662f38f6fe33a9bd56b7e89f38054dd86b43479`. The locked source remains at commit `9aa41d679d121afb8b4cc512d7a162f4f36886c3` with clean git status.
