## 打开哪里、用什么环境

VS Code选择“文件 → 打开文件夹”，打开 `D:\小论文\model_projects`，这样一次能查看三个模型及汇总文件。终端下拉菜单选择Command Prompt（命令提示符/cmd）。Git本身不需要激活Python环境；做Faster实验仍选择 `D:\小论文\model_projects\Faster R-CNN\.venv\Scripts\python.exe`。

## 现在可执行的只读检查

在VS Code的cmd中逐行输入：

```cmd
cd /d "D:\小论文\model_projects"
git status
git log -1 --oneline
git remote -v
```

首次同步完成后应显示main分支、working tree clean（工作区干净）且与origin/main同步；远程应指向 `https://github.com/SujinhaoL/conductor-defect-experiments.git`。如果你之后自己修改文件，出现modified并非错误，不要为追求clean删除自己的修改。把这三条输出反馈给助手即可。

## 怎样看红绿差异

点击左侧“源代码管理”。以后助手修改已跟踪文件但尚未提交时，点击“更改”列表内的文件：左侧是旧版本，右侧是当前版本，红色代表删除、绿色代表新增。新建文件没有旧内容，会全部显示为新增。

如果已提交，可以在终端查看最近一次提交：

```cmd
git show --stat HEAD
git show HEAD -- AGENTS.md
```

某个文件的未提交修改可用 `git diff -- "完整或项目相对路径"` 查看。不要运行reset --hard、clean或checkout覆盖文件来“清理”结果。

## 以后每次如何做

先查看git status和当前实验说明，再准备一个有明确目的的小改动。助手会说明文件/函数/行号、真实diff及科学理由；你可以在提交前看红绿变化。验收后记录提交并报告编号。训练仍用新的实验/运行目录，并记录所用提交、配置及权重。只提交本次已核查范围，不夹带用户其他修改。上传前再查暂存文件，没有自动上传图片、权重或凭证的授权。

默认只跟踪已允许的目录；新类型文件不出现时先检查.gitignore，不要直接git add -f。不要把已有官方源码目录当作根仓库的一部分。Excel在本地由统一CSV生成，原始证据继续保存原处。

## GT177说明了什么，下一步验证什么

GT177是人工标注编号，对应loose（松股）。同类预测中最大IoU约0.615529（框的位置重合程度，0到1），该框分数约0.051652。它已经保存在预测里，也已参与原AP评价；因为低于画图阈值0.30，旧可视化不显示。它说明“看不见框不等于完全没找到位置”，不说明“只把阈值调低就解决低AP”。IoU0.50只是一个判定门槛，0.6155并非十分精确定位；分数也不是经过校准的真实正确概率。

第5轮验证集37个GT中，仍有21个在保存结果中没有同类IoU≥0.50候选，16个覆盖也不是一对一正确检出数。第一步的判断已足够，不需要把网页当作测验继续回答。
